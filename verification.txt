Aim target visibility colors and Magic Bullet investigation

Selected infantry now uses cyan when visible and yellow when occluded while the Aim key is held. Box, skeleton, snapline and label share the selected color; the health bar retains its health-based palette. Both selected colors are editable in Colors > Players and reset with the palette. Existing saved custom selected colors remain the hidden color. Version 5 appends the visible selected color and preserves registry versions 1-4 and shared strings from versions 3-4. Mortar highlighting retains the previous selected color.

Existing snapshot visibility is reused. When both visibility filters are off and player ESP is enabled, the updater traces only the selected player for its highlight. Rendering performs no visibility calls. No timers, threads, imports or additional entity scans were added.

Magic runs on the uncapped update thread after entity collection, through game::tick -> aimbot::tick -> magic_bullet::retarget_all. It writes velocity toward the selected bone, not position. There is no firing-state gate: holding Aim after firing can redirect an eligible airborne round. The menu, target validity, Aim visibility filter and projectile eligibility gates still apply. Tracer trails can outlive active rounds.

Added bounded WD_xetal: Magic: diagnostics on each Aim-key press with Magic enabled: blocked selection reason, or selected target followed by pool availability / counts from that scan. Counts distinguish other ownership, landed, external movement, missing flight time, invalid trajectory data, failed writes and successful redirects. The trajectory math, eligibility checks and thread placement were preserved. The report observes only that press's update; it is not continuous telemetry. A successful write is not proof that engine simulation retained it. Live logs are still required to determine why the user's upward shots do not steer downward; no live fix is claimed.

Validation includes rendering visible/hidden/custom-selected colors and clearing selection; version 4 migration and current settings persistence/sharing; and redirecting an upward round with 1.2 seconds of flight time to a point below it at unchanged speed. Existing ownership, landed-round, tracer, menu, transition and callback tests remain. Initial color pixel assertions sampled antialiased half-pixel edges; the test fixture was aligned to pixel centers, with no renderer changes. The final Desktop suite passed. Live gameplay and FPS were not tested. Existing compiler-option warnings remain.
